## 3. Обязательные правила (нарушать нельзя)

1. **Сначала эталоны и цели, потом замер «до», потом код.** Цели с цифрами записываются в дизайн-док (`docs/<NAME>_V2.md`)
   до первого прогона.
2. **Один и тот же тест до и после.** Лабораторный инструмент (`<Name>_Lab`) не меняется между «до» и «после»; проверки
   несуществующих ещё параметров пишут «n/a».
3. **Цифры, а не впечатления.** Каждое утверждение о звуке — замер на материале владельца или на синтетическом сигнале.
4. **Любое изменение порога, метода или цели после прогона — раскрывается**: в комментарии в коде теста/лаборатории
   («first run used X: ...»), в дизайн-доке (курсивом «first: ...») и в отчёте `docs/reports/v2/V2_REPORT.md`.
   Менять цель можно только если тест был поставлен неверно (мерил не то) — и это объясняется.
5. **Невыполненная цель остаётся невыполненной.** Не подгонять. В отчёте — цифры и почему (пример: HamloMag G2 8x
   −77.8 дБ при цели −90; RedWall R6 громкость 3.95 LU при цели 4.5).
6. **Только добавлять.** Старый проект звучит так же: новые параметры по умолчанию выключены/нейтральны; состояние без
   нового параметра загружается в старом режиме (CLASSIC). Проверка — бит-в-бит.
7. **Идентичность с HPEQ:** ID параметров, диапазоны, state tag, PLUGIN_CODE (BBLB / HmCp / HmUd / HmRw / HmMg),
   bundle id — как у модульного VST3 HPEQ, чтобы его проекты открывались. Новые параметры — новые ID.
8. **Исходники HPEQ не трогать.** Код копируется в репозиторий плагина и развивается там; что откуда — в `docs/SYNC_WITH_HPEQ.md`.
9. **Сверку с HPEQ (Reference tool) сейчас не гонять** — владелец сказал тестировать сами плагины, HPEQ подключим позже.
10. **Коммит на этап, только свои файлы.** Никогда: stash, reset, переключение веток в чужих рабочих копиях, force-push.
    Коммиты заканчиваются строкой `Co-Authored-By: ...` агента. Пуш — только когда владелец попросил.
11. **Экран пресетов — всегда слева сверху, одно место во всех плагинах** (дизайн-прямоугольник 56, 20, 336×116 на
    сцене шириной 1180; `Source/UI/PresetScreen.*` — один и тот же файл во всех репозиториях, менять синхронно).
12. **Свои названия.** Не копировать фирменные имена чужих продуктов (Decapitator «Punish/Thump/Steep» → OVERLOAD /
    BUMP / 24 DB). Не воссоздавать конкретные чужие плагины — брать опубликованное поведение как ориентир.
13. **Аудиопоток без аллокаций**, результат не зависит от размера блока (тест: блоки 1 / 64 / 127 / 512 / 4096 после
    prepare(256) — бит-в-бит), латентность фиксированная и сообщается хосту.

## 4. Порядок работы над модулем (так сделаны все четыре)

### Этап M0 — вынос из HPEQ
1. Новый репозиторий `E:\Hamlo<Name>` по каркасу соседнего (CMake, CMakePresets, cmake/, Assets/, Installer/, UI/BlackSteel,
   PresetScreen, ModuleHelp.h, Tests/TestMain, TestSignals.h).
2. DSP и панель копируются из HPEQ почти дословно: меняются только namespace (`hpeq` → `hamlo`) и include настроек.
   Раскладка параметров — та же, что в HPEQ (`<X>Settings.h` с `slot::k...` теми же индексами), чтобы код читался как в HPEQ.
3. Parameters.h — из `E:\HPEQ\Source\Standalone\ModuleVariant.cpp` (`make<Name>()`), пресеты — из
   `E:\HPEQ\Source\Core\ModulePresets.cpp`, справка — из `E:\HPEQ\Source\UI\ModuleHelp.cpp`.
4. Процессор как модульный плагин HPEQ: фиксированная латентность F (максимум из `maximumLatencySamples` в ModuleVariant),
   dry выровнен по латентности слота, MIX с рампой 20 мс (точно на 0 и 1), ON-кроссфейд 20 мс.
5. Если элемент панели попадает под экран пресетов (слева сверху) — перенести его (пример: рычаг SPEED в HamloMag).
6. Тесты, pluginval 5–10 (+ validator на 10), Steinberg validator `-e` (537/537), установщик, `docs/reports/M0_EXTRACTION_REPORT.md`, коммит.

## 5. Как принимаются решения (принципы, проверенные на этих модулях)

- **Новое — отдельными параметрами**, а не новыми пунктами старого choice: расширение choice сдвигает нормированные
  значения автоматизации. Исключение (8x в OVERSAMPLE) — только с записью в доке.
- **Каждый пресет-рецепт осмыслен:** у него назначение и строка-описание (note) на экране, которая говорит, что он
  делает (модель, атака/релиз и т.д.).
- **Жанр через физику, а не через случайные цифры:** релиз от темпа жанра (1/16 при 90 / 140 / 132 / 174 BPM), у быстрых
  жанров короче look-ahead / быстрее SPEED, у Boom Bap — плотнее тело и винтаж (SP-1200, ламповость), у Trap — 808,
  клик кика поверх 808, жёсткий вокал; Techno — склейка шины и «дыхание» на четверть; DnB — быстрые релизы, хлёсткий
  снейр, параллельная обработка брейков.
- **Отдельные удары** (кик/снейр/хэты/перкуссия) в лимитере — короткий релиз внутри удара (BB 30, Trap 22, Techno 20,
  DnB 15 мс), иначе лимитер просто приглушает весь удар.
- **Параллельная обработка** (MIX < 100 %) для smash/crush — чистый удар остаётся сверху.
- **Метрика должна мерить то, что задумано.** Каждый раз проверять, не обманывает ли метрика (см. раздел 7).

## 6. Жанровые пресеты (200 на плагин)

- 4 жанра × 50: Boom Bap, Trap, Techno, DnB. Группы и количество на жанр: Kick 6, Snare / Clap 6, Hats / Cymbals 5,
  Percussion 4, Drum Bus 7, 808 / Bass 5, Vocals 5, Keys / Piano 4, Samples / Melody 4, Master 4.
- Названия — из подстилей HPDG: BB Classic, Dusty, Jazzy, Gold, Underground, Lofi; Trap ATL, Dark, Cloud, Rage, Memphis,
  Luxury; Techno Peak, Hypnotic, Minimal, Detroit, Dub, Acid, Hard; DnB Modern, Roller, Liquid, Neuro, Jump-Up, Break.
- Рецепты пишутся вручную в `Tools/genre_presets.py` (таблица на жанр), генератор пишет `Source/Plugin/GenrePresets.inc`,
  который включается в `factoryPresets()` после старых пресетов. Поля пресета: genre, group, note, material, depth.
- **Калибровка** — главный регулятор «силы» подбирается бисекцией на материале группы (клипы, самые громкие 10–20 с,
  −18 dBFS RMS, пик не выше −3 dBFS; миксы −14), чтобы попасть в середину полосы глубины (Gentle / Medium / Heavy):
  - компрессор: THRESHOLD по среднему GR (1–3 / 3–6 / 6–12 дБ);
  - лимитер: LOUDNESS по «работе» = max(снижение крест-фактора, средний GR лимитера) (0.5–2 / 2–4 / 4–8 дБ);
  - транзиент-шейпер: не калибруется (V2 не зависит от уровня), проверяется направление контраста атака/тело;
  - сатуратор: DRIVE по доле насыщения N = y(x) − 2·y(x/2) относительно выхода (−36..−24 / −24..−14 / −14..−4 дБ).
- **Проверка** (`<Name>_PresetLab check`) → `docs/reports/presets/genre_presets_check.md`: в полосе, пик в норме,
  изменение уровня в пределах, уникальность **внутри группы** (одинаковые значения в одной группе у разных жанров —
  ошибка рецепта), конечность. Цель — 200 / 200; провалы чинятся рецептами (и раскрываются), не подгонкой полос.
- Пресеты без genre — «Factory» (пресеты HPEQ и прежние) — не меняются.

## 7. Найденные ловушки (уже стоили времени — не повторять)

- **Пики материала:** при −18 dBFS RMS хэты и перкуссия пикуют выше 0 dBFS → держать пик клипа ≤ −3 dBFS.
- **Крест-фактор и «защита пиков»:** режимы, держащие пик (UDARNIK, PROTECT), обманывают крест-фактор — мерить контраст
  атака/тело по ударам (0–10 мс против 25–100 мс), как `HamloUdarnik_Lab`.
- **Ограниченные гармоники:** у HamloLaw гармоники ограничены сверху — «больше драйва + вернуть уровень» работает
  наоборот. Нелинейную часть мерить через N = y(x) − 2·y(x/2), а не y − x (линейные фильтры модели забивают разницу).
- **Плотный луп** почти не даёт контраста атака/тело — для таких целей нужны чистые синтетические удары (лупу — в отчёт).
- **Стартовый фейд блока цвета** из сухого сигнала, который потом толкается на LOUDNESS, бил в потолок (RedWall) — включённая
  с начала стадия стартует сразу полностью.
- **DAC-образ ≠ алиасинг:** для тона ниже Найквиста устройства компонента «rate − f» — образ ЦАП, а не алиас входа.
- **LUFS с гейтом:** сравнение «вся мощность» и интегральной громкости расходится; сопоставлять с гейтом.
- **Совпадения рецептов** между жанрами у лимитера (мало параметров) — разводить по физике жанра (look-ahead, темп).
- **Инструменты Windows:** heredoc в bash ломает `\t`/`\n` внутри Python-строк — писать скрипты в файлы и запускать
  `python -I файл.py`. pluginval — GUI-приложение: запускать `Start-Process -Wait -PassThru -WindowStyle Hidden`, по одному уровню.
- **VST3 в хосте:** ID параметров — хеши; сопоставлять по имени и порядку вхождения (два параметра «Release» в RedWall).
- **Долгие прогоны** (калибровка 200 пресетов — до часа) — запускать в фоне, не опрашивать в цикле, потом проверить
  весь вывод; если процесс прервался — продолжить с недостающих (у `calibrate` есть фильтр по именам: третий аргумент
  `"Name1;Name2"`).
